# Recent Screenshots

A native local menu-bar app showing your latest 10 saved screenshots.

Build with `bash scripts/build.sh`, then open `build/Recent Screenshots.app`.
Rest your cursor in the centered 75% of the top edge on either display for 0.3 seconds to reveal thumbnails. On a notched display, the hot zone includes the area immediately below the notch; on other displays it is the top 3 points. The shelf opens near your cursor and stays within the display bounds. Move away to hide after a 150 ms grace period, or click outside to dismiss immediately. The narrow corridor between the reveal edge and shelf stays active so you can reach the thumbnails. Open context menus remain usable. Dismissing does not immediately reveal again until you leave and re-enter the hover zone. Click to copy the full-resolution image; right-click to open or show in Finder. The latest 10 screenshots appear in a fixed two-row, five-column grid, newest first. No scrolling is needed. The shelf opens near the initial hover point and stays there; it does not follow the cursor. Controls → Hover zone width offers centered 25%, 50%, 75%, and 100%; 75% leaves 12.5% inactive at each corner. The setting is remembered. The shelf has a **Controls ▾** button, as well as the menu-bar controls.

## Install and start automatically

Open `build/Recent Screenshots-0.6.0.pkg` with macOS Installer. It stops the current user's running app, installs version 0.6.0 at `/Applications/Recent Screenshots.app`, and retains screenshot history and preferences. After installation, open the Applications copy. This local installer is unsigned; its payload is ad hoc signed. Build a fresh installer with `bash scripts/make-installer.sh`.

Alternatively, quit the running development copy and move `build/Recent Screenshots.app` to `/Applications` yourself. In **Controls ▾**, enable **Open at login**. This uses macOS's native login-item registration, without a separate background helper or LaunchAgent. If macOS requires approval, the app opens Login Items settings. Login registration is only enabled after the app is in Applications, so it does not point at a temporary build path. Automatic startup occurs when you log in to your account.

The menu-bar icon provides manual reveal on the display under your cursor, refresh, folder selection, hover toggle, clipboard toggle, and Quit. Desktop scanning accepts macOS-tagged screenshots only. A folder you explicitly choose accepts all supported images.

**Clipboard images are supported and enabled by default**, as requested for Logitech's screenshot-to-clipboard button. The app checks for changes every 0.5 seconds, saves PNG/TIFF images locally, and combines them with saved screenshots to display the latest 10. It also imports an image already on the clipboard at launch. It ignores text, file icons, and items marked concealed/transient/autogenerated. Images copied from browsers can also be captured; it cannot identify their originating screenshot shortcut. Clicking a shelf image does not add it back to history.

The last 10 clipboard copies are kept in `~/Library/Application Support/RecentScreenshots/Clipboard`. Older app-created copies are removed automatically. Original screenshots are untouched. Turn off **Keep copied images** in Controls to stop monitoring; stored images remain available. There are no network calls or screenshot-setting changes. Login registration is opt-in.

Folder access, clipboard storage, and thumbnail work run in the background. Each source caches up to 10 small thumbnails; only the 10 newest combined items are displayed. Hover checks run at 10 Hz. Hidden panels are removed from the window list. Hover works over full-screen apps as well; disable hover while presenting or screen sharing.

This development build is ad hoc signed, not Apple notarized. Rebuilding can cause macOS to request folder access again. Build artifacts target this Mac's architecture. Original screenshots are left untouched.

Run fixture-based checks with `"build/Recent Screenshots.app/Contents/MacOS/RecentScreenshots" --self-test`. They cover newest-first ordering, thumbnail decoding, screenshot metadata, PNG/TIFF clipboard capture using a private test pasteboard, exclusion of text/concealed/file data, the clipboard storage limit, shared display boundaries, notch geometry, the cursor corridor, dismissal timing, menu retention, configurable hover-width boundaries, two-row/five-column grid layout, and shelf layout. The test does not change your clipboard. AppKit requires access to the logged-in macOS GUI session for these checks. The installer payload and destination are verified by expanding the package; a privileged installation and native login registration have not been run by the agent.

Initial local measurement: 240 KB app bundle, approximately 29 MB resident memory, and 0.0% sampled idle CPU. With clipboard images cached, a subsequent sample showed approximately 54 MB and 0.1% CPU. Memory varies with screenshots and copying; PNG copying now avoids full-size TIFF conversion. Disk storage is bounded by image count, not total bytes. Notch and multi-display geometry have fixture coverage. Live hover and native login registration still need manual acceptance testing; the user confirmed clicking and showing work.

## App icon

The app bundles `assets/app-icon.png` as a native multi-resolution `.icns` icon for Finder and Applications. The menu-bar icon remains monochrome for legibility. The original generation prompt and method are recorded in `assets/icon-prompt.md`.

## Clear history and compact height

With five or fewer images, the shelf is one row tall; six to ten images use two rows. The trash button beside Controls clears history: app-owned clipboard copies are moved to Trash, while saved screenshot originals remain untouched and are hidden from the shelf until new screenshots arrive. Clear state persists across restarts. The current clipboard is not erased or re-imported immediately after clearing. The app icon is a simple black-and-white mark.
